## 1. 产品目标

让调皮的桌宠在用户持续工作时，对长期静止区域提供有策略的间歇覆盖、动态替换或调暗；保持操作可用，提供可核实的显示统计。多屏 GPU 帧同时支持静态分析和未来视觉读取。完整需求见 [PRODUCT](PRODUCT.md)。

首个核心版本提供视觉/API/任务接口与测试适配器；真实模型、真实业务连接和丰富内容库属于后续可独立启用的能力包。允许拼接源码和模块，须经过许可、边界适配与隔离验证。

## 2. 目录与权威模型

路径及实际状态以 [根 README](../README.md) 为登记入口。文档角色索引见 [docs/README](README.md)。

PRODUCT 管需求；PLAN 管模块、执行、门禁与状态；ARCHITECTURE 管设计；CONTRACTS 管跨模块数据；ASSET-PACKS 管资源；OPEN-SOURCE 管研究依据与候选准入。实现 schema 将从语义规格派生并保持版本同步。用户明确变更优先，修订相应规格和工作包后继续。

主方案 Godot .NET + Windows 感知，WGC 为首个采集后端。M09.P1 必须先验证 Hyper-V 显示/GPU 能力；技术栈内具体绑定库、IPC 与渲染方案根据该包的证据确定，不能绕过隔离要求。

## 4. 模块契约与闭合条件

### M01 多屏 GPU 帧

- 目的：为每块有效显示器提供真实、新鲜、可控的 GPU 帧。
- 输入/输出：RuntimePolicy → DisplayTopology、FrameLease、CaptureHealth（I01/I02/I10）。
- 所有数据：显示身份/epoch、会话与纹理池、设备状态、采集错误；依赖 M09 的策略与生命周期。
- 边界：不修改静态时间图、覆盖账本、动作或用户资源；不依赖模型。
- 失败：分屏隔离故障，旧帧标 stale，热插拔/设备丢失重建，取消旧 epoch 租约。
- 测试/证据 T01：帧释放、双屏、异步时间戳、混合缩放/旋转/HDR、插拔/恢复、无新内容与失效区分；按实际硬件能力记录。
- 闭合 C01：WGC 主路径、契约适配/后端不可用行为、资源上限和恢复通过；真实多屏/HDR覆盖不足保留门禁。

### M02 静态区域观察

- 目的：给出区域稳定时间、特征与可信度，识别用户固定线框。
- 输入/输出：有效帧/健康/自身覆盖区域 → ObservationTile（I02/I03/I16）；拥有特征历史与静态图。
- 依赖 M01 只读帧，M09 只读策略；自身遮挡区域通过已知渲染描述辅助处理，不写 M01/M03 状态。
- 失败：不可观测不累计为静态；局部恢复重新建立可信观测；健康缺失触发保守降级。
- T02：固定细线、局部视频、闪烁光标、窗口移动/遮挡、采集超时、自身动画、HDR色域变化；合成输入与许可真实输入分别记录。
- C02：测试集达到冻结阈值，细线/光标不导致整区误清零，故障状态和可信度正确。

### M03 覆盖调度与账本

- 目的：在打扰约束内分配区域、运动和效果，核实实际服务。
- 输入/输出：ObservationTile、InteractionContext、实际回执/通知意图 → ActionPlan、EffectRequest、CoverageLedger（I03—I08/I12）。
- 独占覆盖账本、随机种子、区域优先级、计划生命周期；只读其他模块的公开状态。
- 边界：不读取皮肤私有资源，不篡改静态事实/任务状态，不以预计范围登记实际完成。
- 失败：无观察采用低打扰巡游或暂停定向任务；无回执不给覆盖信用；超时可撤除/重派。
- T03：公平性、预算、取消、重放、动作拒绝、通知风暴、稀疏 alpha、加色效果与黑幕计量。
- C03：固定种子可复现，实际覆盖反馈改变目标选择，操作区优先避让，统计口径与误差明确。

### M04 宠物运动与动作表现

- 目的：执行路线、飞行、攀爬、跳跃和即时互动，兼顾自然感与确定控制。
- 输入/输出：ActionPlan、InteractionContext、AssetSetResolved → MotionState、锚点、身体覆盖回执（I05/I07/I08/I09）。
- 拥有位置/速度/运动模式与动作仲裁；读取 M06 解析资源，不改资源包和覆盖优先级。
- 失败：能力缺失返回降级/拒绝，拓扑改变改道，动作中断回安全 idle，物理与路径互斥写入。
- T04：目标到达、边界、跨屏负坐标、输入避让、拖拽释放、动作缺失和取消。
- C04：动作与桌面坐标正确，角色外观替换后运动控制保持，覆盖形状来自实际表现。

### M05 局部特效

- 目的：提供可设计、可停止、可计量的魔法和局部遮挡。
- 输入/输出：EffectRequest、锚点、解析效果/可选桌面纹理 → RenderCoverageReceipt（I06—I09）。
- 拥有效果实例与 GPU 资源，预算内渲染；不改宠物物理/静态时间图/账本。
- 失败：效果异常/超时主动撤除，预算超限降级，代次过期拒绝，默认穿透与焦点保护。
- T05：身体外渲染、真黑、透明/加色口径、窗口层级/任务栏、终止、无效资源和设备重建。
- C05：基础烟雾/黑幕可独立替换，实际 alpha/形状可核算，无残留遮挡，特效边界与输入独立。

### M06 资源组合与包管理

- 目的：独立设计、导入和组合皮肤/动作/效果，控制兼容与安全。
- 输入/输出：包、BindingProfile、切换请求 → AssetSetResolved、验证诊断（I09/I13）。
- 独占包索引、摘要/许可记录、兼容解析与 generation；模块通过不可变资源引用使用。
- 边界：包内声明不直接执行 OS、联网或模型调用；不依赖特定宠物名称。
- 失败：保留上一完整组合，兼容失败明确拒绝或按声明降级，引用释放后回收。
- T06：ASSET-PACKS 的替换矩阵、跨 rig、路径逃逸、资源炸弹、版本循环、运行中切换。
- C06：至少 2 皮肤×2 动作×2 效果的兼容组合证明独立替换；跨 rig 要么绑定成功，要么正确拒绝。

### M07 视觉模型扩展

- 目的：为未来画面理解提供同一帧源的受控接口。
- 输入/输出：VisionRequest、允许的 FrameLease → VisionResult（I10/I11/I14）。
- 拥有请求、ROI 处理、提供商能力与超时；凭据仅引用 M09，不长期占有帧或改核心事实。
- 失败：模型/网络不可用返回明确状态，保持覆盖和运动可用；未授权上传拒绝。
- T07：选屏/窗口/ROI、过期帧、跨屏时差、取消、色彩转换、策略拒绝和模拟模型失败。
- C07：schema、测试提供商、帧路由与策略闭环通过；真实视觉模型属于后续包，不计为已接通。

### M08 API 汇报与任务监控扩展

- 目的：把外部工作的真实状态转为有节制的宠物汇报。
- 输入/输出：认证 IntegrationEvent/快照/心跳 → TaskState、通知意图（I11/I12）。
- 拥有规范任务状态、序列/幂等记录与来源 freshness；模型不得决定完成，进程存活不代表进度。
- 失败：来源失联标 unknown/stale，拒绝越权/超限/畸形消息，风暴合并；不包含任意命令执行。
- T08：独立客户端认证、本机绑定、多来源身份、重复/乱序、等待输入、退出/失联和长文本。
- C08：一个真实本机接口和模拟任务源端到端通过；具体 Agent/业务适配器另立模块所属扩展包。

### M09 宿主、设置与平台

- 目的：安全常驻、每屏策略、即时暂停、集中数据角色与隔离工程能力。
- 输入/输出：用户设置/系统事件 → RuntimePolicy、InteractionContext、生命周期（I01/I04/I13）。
- 拥有策略、凭据引用、配置路径、宿主生命周期；按需求最小读取输入状态，不记录按键正文。
- 依赖 Windows/Godot/受控系统接口；不替其他模块写事实或使用日用发布为开发环境。
- 失败：暂停优先、配置损坏回安全默认，焦点/交互不可用采取保守策略；VM/硬件能力不足留下明确缺口。
- T09：配置/权限、路径集中、暂停/恢复、多屏偏好、原生焦点与穿透、隔离初始化/清理。
- C09：Hyper-V 项目控制/身份/预算与回执已建立，宿主功能和数据路径通过；真实显示能力缺口有验收路径。

### M10 工程证据、集成与验收

- 目的：能复现工程结论、判断真实覆盖，支撑最终产品验收与后续发布。
- 输入/输出：各模块结果/指标 → EvidenceReceipt、门禁矩阵、发布候选记录（I15）。
- 拥有验收定义/证据索引与门禁状态；原始结果仍由实际执行层出具，展示状态不能替代证据。
- 边界：不把虚拟显示验收写成物理显卡通过；不因预算到期或文档完成关闭未完成门禁。
- 失败：测试失败/超时/清理未完成显式保留；证据身份不匹配即不可用于通过。
- T10：故障注入、回执身份核验、资源/隐私、长稳、许可、清理与复现。
- C10：要求的隔离模块与集成门通过，集中工程审查和人类最终体验按对应门完成。

### 工作包权重规则

每模块 P1（契约/核心试验）占模块权重 30%，P2（模块闭环与验收）占 70%。P1 只有产出指定试验/接口证据才计分，已有规划文字不计。P2 子任务采用复杂度 S=1/M=2/L=3 的相对分值分配；验收强度与返工风险用于修订分配，不自动制造精确工期。下一节列出每包复杂度、串并行类、验证强度和返工敏感度。

## 9. 测试、证据与门禁

### 工程验证要求

所有 Python/Node 开发实验、预检、测试、构建、预览在登记的 Hyper-V 客体运行；宿主仅编辑、Git、同步和可信原生控制。程序源码和一致输入只读进入；客体内执行私有副本。具体工具命令在选定工具链后写入对应工作包，当前不编造可运行控制脚本或成功结果。

每次运行捕获 project/run/nonce/VM、源码与验证 SHA、父盘代次/指纹/有效期限、输入范围与字节数/指纹、磁盘和时间预算、真实逐层退出码/异常/超时。导出仅允许的有界统计与控制回执；画面/业务内容保持客体私有，完成后按登记生命周期处置。

### 初始验收目标与冻结点

以下为建议试验目标，不是已测性能，G0 试验后依据环境修订并冻结可复现基准；重大降标需说明产品影响并进入集中工程判断。

| 项目 | 初始目标 | 测量边界 |
|---|---|---|
| 多屏 | 至少双屏；增加负坐标、混合缩放、横竖屏组合 | 显示器/适配器/分辨率/系统版本逐项记录 |
| HDR/SDR | 声明支持的混合模式色彩处理正确 | 对比输入与输出；无实际能力时保留未覆盖 |
| 静态识别 | 固定细线稳定，局部视频与光标不污染邻区 | 冻结夹具、标注真值；量化误报/漏报、边缘保持和时长误差 |
| 覆盖计量 | 解析黑幕测试误差不超过 5%，稀疏透明/加色分类正确 | 按像素面积×时间与参考结果比较，明示近似误差 |

| 接口 | 视觉模拟与认证任务入口都能取消/失败/恢复 | 端到端与缺失模块测试，真实外部接入独立登记 |
